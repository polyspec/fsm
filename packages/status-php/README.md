# polyspec/status-php

[한국어](README.ko.md)

The PHP consumer of status (`docs/plans/status-v1.md`, C-2). The package is private and is a test bed: it is not published.
It shows how the generated PHP code of a status definition is used, and it checks that code against the conformance vectors.
The generated namespace is `Polyspec\StatusTest` (the test bench's choice of `--php-namespace`); each machine is a sub-namespace
`<ns>\<Pascal machine key>`, such as `Polyspec\StatusTest\Order`.

- `src/`: generated by `status-gen gen --kind php` (do not edit). Each machine has `<Pascal>/State.php` and `Event.php` (backed
  enums), `Step.php` and `functions.php` (the functions of `docs/spec/status.md`, B-6, loaded by composer `autoload.files`);
  `Status/Code.php` and `Status/Error.php` are the shared error code enum and exception.
- `tests/Vectors.php`: the vector cases of every machine, generated by `status-gen vectors --kind php`.
- `tests/ConformanceTest.php`: one PHPUnit test per vector case, named `test_<feature>__<id>` in its data set name, which
  asserts the result of the generated function or its error code. It uses the public API only, so the php extension package
  runs the same file.
- `examples/persist.php`: the persistence pattern of `docs/spec/status.md` (B-4) on SQLite with polyspec orm. The persist cases
  run it.
- `examples/model/`: the orm model generated from the root `schema/persist.dbs`.

From this directory: `make install` installs the pinned dependencies (`composer.lock`), `make gen` regenerates the files above,
and `make test` runs the tests through `scripts/kit/run-tests.mjs`. The root `make gen-check` checks that the generated files are
current. `Error::getCode()` returns the code string (such as `E_CONFLICT`), because PHP keeps the protected `$code` of
`Exception`; the other fields of the error are the state codes and the event index.
