# polyspec/fsm-php-ext

[한국어](README.ko.md)

The PHP extension kind of fsm (`docs/plans/fsm-v1.md`, C-2). The package is private and is a test bed: it is not published.
It builds the generated state machines of a fsm definition as one PHP extension, `polyspec_fsm_test`, and checks that
extension against the same conformance vectors as the php package. The public API is the one of the php kind: the namespace
`Polyspec\FsmTest`, each machine is a sub-namespace `<ns>\<Pascal machine key>` (such as `Polyspec\FsmTest\Order`), with
the enums `State` and `Event`, the class `Step`, and the functions `initial`, `code`, `key`, `fromCode`, `isFinal`, `eventsFrom`,
`target` and `apply`; the shared `Polyspec\FsmTest\Fsm` holds the enum `Code` and the exception `Error`.

- `src/`: generated by `fsm-gen gen --kind php-ext` (do not edit). `order.c` is one machine, `fsm.c` the shared classes and
  the module entry, `php_polyspec_fsm_test.h` the header, `polyspec_fsm_test_arginfo.h` the arginfo, `polyspec_fsm_test.stub.php`
  the declarations for editors, and `config.m4` the build declaration that phpize reads. `make build` adds the phpize output in
  `src/`, which Git ignores.
- `tests/Vectors.php`: the vector cases of every machine, generated by `fsm-gen vectors --kind php-ext`. It is byte-identical to
  the php package's `tests/Vectors.php`.
- `tests/ConformanceTest.php`: a copy of the php package's file, made by `make gen`. It runs one PHPUnit test per vector case,
  named `test_<feature>__<id>`. It uses the public API only, which is why the same file runs against both packages.
- `examples/persist.php`: a copy of the php package's file, made by `make gen`. It is the persistence pattern of
  `docs/spec/fsm.md` (B-4) on SQLite with polyspec orm; the persist cases run it.
- `examples/model/`: the orm model generated from the root `schema/persist.dbs`.

From this directory: `make install` installs the pinned dependencies (`composer.lock`, the same packages as the php package),
`make gen` regenerates the files above, `make build` compiles the extension with `phpize`, `./configure` and `make` in `src/`,
and `make test` builds it and runs the tests through `scripts/kit/run-tests.mjs`, loading the built module with
`--php-extension`. `make gen` runs after a build without `make clean`: the phpize output is git-ignored, so gen skips it (it is
neither refused nor removed). `make clean` removes the phpize output of the build. The root `make gen-check` checks that the generated files and the copies are current, and
`make parity-php-ext` checks that every vector case ran once and passed.
