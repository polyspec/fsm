## Unreleased

- S-18-1: the commands `fsm-gen`, `fsm-db` and `fsm-gui` exist. They are the `bin` entries of `packages/fsm-compiler/package.json` (new, without dependencies), `packages/fsm-db/package.json` and `packages/fsm-gui/package.json`; each file starts with a node shebang and is executable, and `npm install -g ./packages/<package>` from a clone links the command onto the PATH. S-18 had renamed them in the documents only. A test in each package installs it offline into a temporary npm prefix and runs the command; the GUI usage line names `fsm-gui`.
- S-15-1: `fsm-db install [--project <dir>]` installs the schema of `schema/fsm.dbs` into the database that `fsm.config.json` names, through orm `utils().schema().install`, so a database gets its tables without code. On a new database `fsm-db check` fails with `no such table: machine` (exit 1), `install` prints `[fsm-db] install: ok` (exit 0), and `check` then passes. A second `install` changes nothing and exits 0; on a database that has only some of the tables orm rejects the install with `CONFIG`, which is printed with its stack (exit 1), with no fallback (observed with orm v0.0.7). `packages/fsm-db/README.md` and `README.ko.md` are the user guide of the DB store. The spec (B-2) and the plan (C-6) list the commands; the spec's `copy` line is corrected to the flags the CLI has (`--to` or `--from` with `--root`; the DSN comes only from the variable that `dsnEnv` names). The install is tested as processes on SQLite in `packages/fsm-db/tests/cli.test.mjs`.
- S-18: the library is renamed from `status` to `fsm` everywhere (R12). The packages are `packages/fsm-*`, the commands are `fsm-gen`, `fsm-db` and `fsm-gui`, the files are `fsm.config.json`, `fsm.lock.json`, `machines/*.fsm.json`, `*.fsm.mmd`, `schema/fsm.schema.json` and `schema/fsm.dbs` (dbspec `fsm`), the documents are `docs/spec/fsm.md` and `docs/plans/fsm-v1.md`, the generated shared module is `fsm` (`fsm.Error`, `<ns>\Fsm\Error`, the module `fsm` of each backend), and the reserved machine key is `fsm`; `status` is an ordinary key again. The manifests carry the names `polyspec_fsm`, `polyspec-fsm`, `@polyspec/fsm-*`, `github.com/polyspec/fsm-go`, the namespace `Polyspec\FsmTest` and the extension `polyspec_fsm_test`. The consumer's status column and the process and test statuses keep `status`. `scripts/check-name.mjs` (`make name-check`) fails on a tracked file or path that names the library `status` outside its allowlist, and the goldens and generated files were regenerated by `fsm-gen`. AGENTS.md and the plan list `name-check` among the tools that enforce the rules, the scope is R1–R12, and a document names the old name only as "old name `status`".
- S-11-2: the python package drops its color workaround. `packages/status-python/Makefile` no longer sets `PYTHON_COLORS=0` in `make test`, because kit v0.0.15 (K22) makes run-tests python set `NO_COLOR=1` and `PYTHON_COLORS=0` itself. Without the kit setting, unittest colors its verbose lines under `FORCE_COLOR=3` and the reporter does not read them: the v0.0.14 runner failed 10 of 10 runs with the line removed, and the v0.0.15 runner passed 10 of 10. `make test-python` passes 89 of 89 cases with `FORCE_COLOR=3` and without it.
- S-16-1: the GUI test hang is fixed at its cause. The kit v0.0.15 sync (K23) makes the stdout pipe of a test child blocking (`scripts/kit/test-load-check.mjs`). On the asynchronous pipe, the `process.exit` of the test child dropped the results still queued in it, so a file reported fewer results than it ran, and the runner could print "the test did not finish". With 600 cases in one file, v0.0.14 lost results in 12 of 30 runs, v0.0.15 in 0 of 30, and v0.0.15 with only the blocking lines reverted in 10 of 30. The sync also brings K21 (the node file group under `--cwd`) and K22 (run-tests python sets `NO_COLOR=1` and `PYTHON_COLORS=0`). Before the test change, `make gui-test` passed 20 of 20 runs, 4 at a time (210 results each), and `make compiler-test` passed 20 of 20 (302 results each); the hang did not reproduce in this checkout. The per-call 20-second deadline in `packages/status-gui/tests/mermaid-parse.test.mjs` only hid the hang, so it is removed; the runner already gives each case its own timeout. The flat tests (one per reserved word and position, and one per ordinary key) are kept, because each case has its own name and result. After the change, `make gui-test` passed 20 of 20 runs.

- S-14-3: `gen` and `vectors --kind` skip the git-ignored files of their output directory (`packages/status-compiler/src/cli/write-generated.mjs`).
