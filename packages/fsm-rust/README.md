# fsm-rust

[한국어](README.ko.md)

The rust consumer of fsm (`docs/plans/fsm-v1.md`, C-2). The crate is private and is a test bed: it is not published.
It shows how the generated rust code of a fsm definition is used, and it checks that code against the conformance vectors.

- `src/`: generated by `fsm-gen gen --kind rust` (do not edit). Each machine has `<machine>.rs`; `fsm.rs` holds the
  `Code` and `Error` types; `lib.rs` declares one module per machine and `fsm`.
- `tests/vectors.rs`: the vector cases of every machine, generated by `fsm-gen vectors --kind rust`. One `#[test]` per case,
  named `test_<feature>__<id>`, calls a check function of `tests/conformance.rs`; the persist cases are `#[tokio::test]`.
- `tests/conformance.rs`: the check functions, and the test crate that includes `tests/vectors.rs` and `examples/persist.rs`.
- `examples/persist.rs`: the persistence pattern of `docs/spec/fsm.md` (B-4) on SQLite with polyspec orm. The persist
  cases run it and assert the stored code after each run.
- `build.rs`: generates the orm models of the root `schema/persist.dbs` into `OUT_DIR`. There is no `examples/model/` directory,
  because this build script is the rust model generator (the declared difference of rust in `contracts/layout.json`).
- `Cargo.toml` and `Cargo.lock`: the orm release `v0.0.7` (`polyspec-orm`, `polyspec-orm-build`) and `tokio`, pinned by git tag.
  The toolchain is `rust-toolchain.toml` at the root.

From the checkout root, `make -C packages/fsm-rust install` fetches the crates, `make -C packages/fsm-rust gen` regenerates
the files above, and `make test-rust` runs the tests through `scripts/kit/run-tests.mjs`. The root `make gen-check` checks that
the generated files are current.
